# ツリー通信v2 — 既存機能を残す追加25画面

2026-10-05。PC 11枚・スマホ14枚を、機能ごとに対比するための画像モック資料です。画像生成には組込みの `image_gen` を使用しています。

[追加25枚のギャラリーを開く](index.html) · [前回の主動線12枚](../2026-10-04-schedule-integrated-v2/index.html)

前回12枚は「予約から開く→メモ→通信→コピー」の主動線を示しました。しかし、M08等に業務や設定への入口を置くだけでは、出欠・送迎、日報、勤務、入力設定、履歴、入出力などの詳細を維持できるか判断できませんでした。今回は実装コードを再監査し、入力項目・操作・状態が見える画面を補います。

これは現行機能を保持する UI 提案です。画像は実アプリの画面変更、実データ移行、共有サーバー接続、操作検証の完了を示しません。各画像の実ファイルは `images/{ID}.png` です。

ギャラリーはPCと対応するスマホを同じ節に並べています。画像を押すと拡大し、拡大表示内で「画面に収める／原寸で見る」を切り替えられます。左右キーで前後へ、Escで閉じます。各画像の直接リンクも用意しています。

## 現在の接続範囲

- 通信V2は、予約V2のスタッフ画面から起動します。通信用の別ログインや独立したグローバルナビを提案するものではありません。
- **通信V2の保存は、利用者ごとのブラウザー内仮保存です。** スタッフ間・端末間の共有、旧通信データの移行、新サーバー接続は未実施です。
- 予約から通信へ、**児童・日付・事業所を自動で引き継ぐ処理はありません。** 通信側で選んだ対象を表示します。
- 予約V2自身には連絡記録の下書き保存・公開・更新・非公開、保護者側の「日々のあしあと」があります。通信V2からその保存・公開経路へは未接続です。
- 入力完了、コピー成功、手動送信確認、保護者公開は別の状態です。コピーだけで送信済みにしたり、完了だけで保護者へ公開したりしません。
- AIバディ、写真、LINE自動送信、共有サーバーと権限設計は今回の補完画像の範囲外です。

## 再監査で補正した点

1. **前回P03の書式ツールバーと「申し送り 0/200」**：現行エディターはプレーンテキストです。太字・斜体・リンク等は現行機能として扱いません。「今後の予定」は独立した保存項目で、80文字は目安です。P08/M13を今後の設計基準にします。
2. **変更履歴**：既存 UI は変更前後の閲覧と旧値コピーです。Appに復元用関数があっても、LogModalから呼ばれていません。「自動復元」を実装済みとは扱いません。バックアップCSV復元は別の機能です。
3. **DocViewer**：コンポーネントと描画処理はありますが、通常UIから選択状態を設定する経路がなく未接続です。支援項目のデータ保持や書出しと、書類編集画面の利用可否を分けます。
4. **手動の並べ替え・全員コピー**：`handleSort`、全員コピー関数は残っていますが、現行UIの呼出しを確認できません。通常の時刻順表示、一人分コピー、選択児童の結合コピーとは区別します。
5. **共有タグ**：`【共有】`付きメモは施設の共有事項にも児童名付きで追記されます。メモを後で編集・削除しても、追記済み共有事項は逆反映されません。
6. **OKワード**：敬称付き語を使う名前検出の除外設定です。全ての個人情報を検査する機能ではなく、登録は一時的な無視ではありません。

## 画像で確認すること・残る確認

対象児童、日付、事業所、保存対象、戻り先、入力中・保存済み・完了の区別を見ます。予約V2の外枠を維持し、スマホでは横長の表を縮小せず、一人分や一設定を縦に扱う提案です。正式ロゴは[提供PNG](assets/official-logo.png)全体と比率を基準にし、生成画像の差異を正式な変更とみなしません。

この25枚は全状態の一覧ではありません。前回M06/P04の複数選択コピー、細かな取消、削除確認、空状態、読み込み中、入力エラー、コピー失敗、保存失敗などは、引き続き台帳と実装確認で扱います。画像に見えない操作を削除するという意味ではありません。M11だけでは日報の特記事項・共有事項が入口のみになるため、M22で入力画面と前7日の記録を補います。

P14/M20は共有接続時の競合比較案です。コードにあるロック・競合の意図を保持しますが、現在のブラウザー内仮保存が別スタッフ間の共有を完成させたとは表示しません。同一UIDの複数端末や、競合中の離脱・保存失敗を含む検証は別途必要です。

このフォルダは資料ギャラリーです。業務データを保存・送信しません。ソースから機能を監査したこと、画像の表示を確認したこと、実アプリの操作が検証できたことは別々に報告します。
