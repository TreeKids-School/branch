コードを再監査して描く、未実装のUI提案です。 前回はメニューの入口だけだった操作について、項目と状態が見える画面を補います。実アプリの操作検証が完了した画像ではありません。

現在の通信V2は、利用者ごとのブラウザー内仮保存・未共有です。予約から児童・日付・事業所を自動で引き継ぐ処理、旧データ移行、通信V2からの保護者公開は未接続です。AI・写真・LINE自動送信は今回の範囲外です。

前回から補正した点と、画像で確認できないこと
  • P08 / M13で補正：前回P03の太字・斜体等の書式ツールバーと「申し送り 0/200」は現行機能ではありません。プレーン本文と、独立した「今後の予定」（80文字は目安）を保持します。
  • DocViewer、手動の並べ替え、全員コピーには通常UIからの呼出しを確認できません。関数の存在を、利用可能な画面の証拠にしません。
  • 変更履歴は変更前後の閲覧と旧値コピーです。「自動復元」は未接続。バックアップCSVの復元とは別です。
  • コピー成功、入力完了、手動送信確認、保護者公開は別の状態です。予約V2自身の連絡記録・保護者閲覧はありますが、通信V2からはつながっていません。
  • P14 / M20は共有接続時の競合比較案です。現在のブラウザー保存がスタッフ間の共有を実現したとは表現しません。
  • 画像は全状態の一覧ではありません。複数選択コピー、細かな取消・削除・空状態・保存失敗等は、前回資料と機能台帳に残して実装時に確認します。

画像を押すと拡大できます。スマホは縮小しすぎず、PCの隣に配置しています。

画面から機能を落とさないための資料です。 ここにあるのは画面構成と操作の提案です。実アプリの保存・公開・共有・移行、データの正しさ、全状態の操作検証が済んだという意味ではありません。

正式ロゴは提供PNG全体と比率を基準にします。生成された画像内に文字や配置の差異があっても、正式な仕様変更とは扱いません。
