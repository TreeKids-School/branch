# 現行機能と追加25画像の対応・訂正表

更新日：2026-10-05。前回のPC4枚・スマホ8枚に、PC11枚・スマホ14枚を追加するための台帳。入口だけの画像を操作画面の確認済みとして数えず、現在のソースで到達する操作、残るデータ・処理、提案する改善を区別する。

この台帳はコードの読取りによる機能監査と画像の設計要件をまとめたもの。画像はUI案であり、実アプリのUI変更、操作テスト、既存データ移行、新サーバー接続、共有や公開の稼働確認を示さない。画像の氏名・本文・日付・件数は表示例である。

## 1. 判定の読み方

| 区分 | 意味 |
| --- | --- |
| **既存・入口あり** | Appから画面を開く操作と、イベント／コールバックの接続をコードで確認。データや状態により表示される操作も含む。実環境で正常動作を検証したという意味ではない |
| **残存データ・処理** | 保存項目・関数・コンポーネントは存在するが、通常の操作入口がない、または現行画面に描画されない。再接続や新しい編集画面を作るなら追加案 |
| **提案改善** | PC／スマホに合わせた再配置、文字付き操作、保存失敗救済、確認画面の整理など。既存で実現済みの保証とは分ける |

現在の通信V2は、予約V2からスタッフ認証情報の必要部分を受けて起動する**利用者別ブラウザー内仮保存版**。予約の児童・日付・事業所の自動引継ぎ、スタッフ間共有、旧データ移行は未接続。予約V2自身の公開・保護者閲覧機能と、通信V2からその経路へ接続できることも別である。

監査の根拠と細かい制約：

- [運営業務の監査](AUDIT-OPERATIONS.md)：出欠、送迎、児童追加、日報、プログラム、勤務。
- [エディター・設定の監査](AUDIT-EDITOR.md)：メモ、本文、予定、名前警告、設定、ロック、競合。
- [入出力・履歴の監査](AUDIT-DATA.md)：CSV、復元、書出し、日誌Excel、印刷、変更履歴、未接続書類画面。

## 5. 画像に描かない状態も保持する

25枚を追加しても、全操作の全分岐を画像で網羅したとは扱わない。実装時に保持し、受入れ確認へ引き継ぐ未描画要件は次の通り。

- **空状態**：児童・職員・記録・プログラム・挨拶・タグ・対象月のデータがない、検索や絞込みが一致しない。
- **中断と取消**：メモ編集取消、挿入選択解除、設定取消、ファイル選び直し、未保存のまま日付・事業所・児童・予約画面へ移動する場合。
- **削除と解除**：メモ・タグ・プログラム・当日参加の削除確認、完了解除、担当解除。M09には当日一覧から外す操作は描いていないが、P05の操作と合わせてスマホ実装にも保持する。マスターや過去記録の削除とは区別する。
- **コピー**：個別と複数選択、結合本文と対象児童の確認、空本文、クリップボード権限拒否／失敗、コピー後も未送信確認の状態。
- **保存と競合**：保存中、取得失敗、ロック取得失敗／他者編集中／期限切れ、手元と保存済み内容の選択、保存失敗後の離脱。ロック中の一覧と競合比較は別状態であり、P14／M20だけで双方を描いたとはしない。
- **入出力**：不正形式、未登録・未照合、対象0件、同一内容の重複、Excelシート未一致、読み込み中、途中失敗、印刷ウィンドウを開けない状態。自動ロールバックや安全な再開を現行保証として追加しない。
- **保存範囲**：本文と予定の自動保存間隔、端末内下書きの実際の対象、設定の個別／まとめ保存を維持する。保存完了を待たず閉じる既存箇所もあるため、新UIで成功を表示する時点は改修時に実処理と一致させる。
- **公開・移行の境界**：入力完了、コピー成功、手動送信確認、保護者公開は別。AIバディ、写真、LINE自動送信、旧データ移行、予約V2への通信連携は今回の25枚の機能補完とは別工程。

正式ロゴの画像全体・比率、予約V2の外枠、通信側の対象事業所・日付・児童を維持する。画像の見た目を整えるために、元データの項目や例外状態を省いた実装へ置き換えない。
