# ツリー通信v2：12画面のUI・UX案

作成日：2026-10-04。全12画面を組込みの **image_gen** で生成した。画像を比較するための [一覧ギャラリー](index.html) を添付している。ギャラリーは生成画像を表示する資料であり、業務アプリの試作実装ではない。

## 提案の中心

**「今日の気づきが、家族の記憶になる。」**

スタッフには、その場で気づきを残し、メモを見ながら文章を整え、届けたことを確認できる流れを用意する。保護者には、具体的な言葉や写真からその日の姿が浮かび、過去の通信も読み返せる体験を提案する。日報・勤務・出欠・送迎・書出しなど、通信作成を支えている業務も残す。

画面の並びは「今日の準備 → 記録する → 通信を整える → 届ける → 振り返る」。毎日使う仕事を前に置き、細かな設定・入出力は専用画面に整理する。現在の大きな画面を小さく縮める代わりに、スマホでは一人分のメモに集中できる案を用意した。

## 既存機能を守るための区別

[FUNCTION-COVERAGE.md](FUNCTION-COVERAGE.md) に、現行ソースの機能を画面番号と対応させた。有効画面、保存されるデータ、残存するが未接続の処理、新しい提案を分けている。たとえば支援記録の項目や全員コピーの関数が存在していても、現在その編集・操作画面が使えるとは限らない。モックを現行機能の動作証明にはしない。

- **入力完了／コピー成功／手動の送信確認／将来の保護者公開**は別の状態。コピーしただけで送信確認済みにしない。
- 自動保存、端末内下書き、完了解除、競合比較、他者の編集ロック、取込み中の操作保護、離脱時の扱いを引き継ぐ。12枚は代表状態の画像で、エラー・空状態・競合等は対応表に記載した実装時の設計項目。
- 通信原文、内部メモ、今後の関わり、支援記録、送迎情報を一緒に保護者公開しない。バディは原文を根拠にした下書きとし、人が確認する。
- 過去との比較で未確認の成長を断定したり、未来の出来事を作ったりしない。「楽しみにしている」は期待の表現として扱い、実際の予約予定とは分ける。

## 見た目と操作の方針

深い緑と生成りを軸に、スタッフ画面は読み取りやすい表と本文を中心にする。保護者画面は一場面を大きく見せ、文章と写真をゆっくり読める余白を増やす。色だけに頼らず状態名を表示し、長押しだけに隠れていた操作にも見える入口を置く。

実装段階では日本語の本文サイズ、スマホのタップ領域、キーボード操作、色のコントラストを実際の画面で確定する。画像生成による微細な文字・数値・日付・アイコン・選択状態は最終仕様ではない。各画像は別の作業時点の作例で、件数や本文は実データの連続した操作履歴を再現していない。

ブランドは [正式ロゴのPNG](assets/official-logo.png) を入力素材に使用した。実装にはこの元PNGをそのまま使い、生成画像のロゴを切り抜いたり、似た木のマークに置き換えたりしない。バディの正式なキャラクター素材は今回確認していないため、新しいキャラクターを発明せず、言葉の欄として表現している。

## 現段階で行っていないこと

アプリ本体・既存データ・認証・Firebase・配信内容の変更、データ移行、API接続は行っていない。現在の予約V2内の通信V2は、利用者ごとに分かれたブラウザー内仮保存版で、スタッフ間の共有サーバーは未接続。モックの保存表示はこの境界に合わせた作例。

Instagram投稿の再編集、保護者アンケートの外部発信、アートの物語・プログラムのコンテンツ管理は、今回の通信業務の12画面には含めていない。将来この蓄積からつなげる別の導線として検討できる。

画像は一枚ずつ目視し、モバイルのロゴ配置と出欠区分の重複を画像生成で修正した。アプリコードの変更がないため、アプリのテスト・ビルド・デプロイは行っていない。
