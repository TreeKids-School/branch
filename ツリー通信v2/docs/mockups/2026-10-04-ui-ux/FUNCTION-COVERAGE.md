# ツリー通信v2 UI/UX案：現行機能の引継ぎ表

調査日：2026-10-04。対象は `ツリー通信v2/src` の有効な画面と保存・書出し処理。実データ、既存サーバー、配信環境の操作検証は行っていない。これはモックアップの機能保全台帳であり、実装・移行の完了報告ではない。

## 読み方と現在の境界

- **現行UI**：`App.jsx` から接続され、描画・操作のコードがあるもの。正常動作を実環境で確認したという意味ではない。
- **データ・処理を保持**：保存項目や残存関数はあるが、現行UIでの操作導線を確認できないもの。新画面で見せる場合は「再配置・追加」とする。
- **将来案**：新しい処理、サーバー連携、保護者公開など。モック上でも稼働済みと表示しない。
- 現在、予約V2内の通信V2は**利用者別のブラウザー内仮保存版**。共有サーバー、既存データの移行、保護者公開は未接続。以下の共有・排他に関する既存コードが、そのまま現在の別スタッフ間同期を保証するわけではない。

出典：[起動時の表示](../../../src/portal/main.jsx)、[認証ブリッジ](../../../src/portal/sessionBridge.js)、[ブラウザー保存](../../../src/portal/browserFirestore.js)。以降の行番号は調査時点。

## 保全が必要な状態・操作

### 作成・確認・コピーを混ぜない

1. **本文なし → 下書き → 入力完了**はスタッフの作成状況。`results[childId].isCompleted` の完了解除も残す。
2. **コピー成功**はクリップボード操作の結果。本文があること、完了にしたこと、コピーしたことから送信成功を導かない。
3. **送信済み**は `dailyTable[childId].sentChecked` による手動チェック。LINE配信結果との連携ではない。
4. 将来の**保護者公開**は別の状態・許可・履歴を設ける。家庭向け本文とスタッフ内部メモを分ける。
5. 兄弟コピーは現在「同じ姓」でグループ化し、同一文を重複除去する。機能自体は保持しつつ、確認画面では結合相手を可視化する。家族IDや送信先の確定と同一視しない。

出典：[App.jsx](../../../src/App.jsx) `handleCopySelectedCommunications`（1930）、`copyAllTreeCommunications`（2010、定義のみ）、`handleCopySingle`（2046）、`sentChecked`（3469付近）。[MemoPanel.jsx](../../../src/components/MemoPanel.jsx) `handleSaveCompleted`（365）、`handleCopyEditor`（388）。

### 保存・同時編集・離脱

- 本文は入力が一段落して約2秒、今後の予定は約800ミリ秒で保存するコード。端末内下書きもある。画面の再配置で「完了するまで保存されない」仕様へ変えない。
- 本文の競合時は自動同期を止め、手元と保存済み内容を表示。「自分の内容を強制保存」「他ユーザーの内容を取り込む」の選択がある。競合中はコピー・完了等を無効化する既存意図を維持する。
- 児童編集を開く前にロック取得。所有者名、取得中、取得失敗、他者編集中を表示。既存ロックはUID判定と約5分の期限を持つ。新共有サーバーの設計時には同一UIDの別端末も整理する。
- パネルを閉じる際の保存、保存完了を待ってからのロック解除、日付・事業所・児童の切替、予約画面へ戻る時の未保存内容を扱う。
- CSV取込中は取込者名を出して他の操作を一時停止するコードがある。進捗・失敗・再開も新UIの設計対象にする。
- 現在のブラウザー仮保存と将来の共有保存は明示的に区別。ブラウザーデータ削除による消失、保存領域の失敗、未移行・未共有を隠さない。

出典：[App.jsx](../../../src/App.jsx) `getChildLockOwner`（245）、`acquireLock`（262）、`releaseLock`（309）、`handleOpenChildPanel`（332）、取込中表示（4236付近）。[MemoPanel.jsx](../../../src/components/MemoPanel.jsx) `handleClose`（109）、競合検出（464付近）、外部記録監視（492）、自動保存（541）、競合比較（930）。

### 当日業務・児童・職員

- 児童の当日参加を削除する操作と、児童マスターや過去の通信を削除する操作を区別する。
- 通常・キャンセル待ち・欠席を往復可能にする。現在の通常枠は10。送迎CSV取込には定員超過時のキャンセル待ち配置通知がある。
- 学習／プログラム／備考はタグ付きメモから取り出す処理がある。見かけ上同じ内容を新UIで別々の正本として編集し、食い違いを生まない。
- 担当の設定・解除、事業所に絞ったスタッフ候補、担当に応じた挨拶挿入を残す。既に挨拶がある場合の二重挿入回避も引き継ぐ。
- 職員勤務の開始・終了は5分単位の入力／丸めがある。日報出力に使用する職種・業務項目を見た目の簡素化で落とさない。
- 児童マスターは検索して当日に追加する導線を確認。バックアップ復元には未登録児童の自動登録確認がある。包括的な児童・職員・事業所の管理画面は別途設計対象。

出典：[AddChildModal.jsx](../../../src/components/AddChildModal.jsx)、[App.jsx](../../../src/App.jsx) `handleAddMultipleFromMaster`（1564）、`updateChildStatus`（1614）、`handleAssignStaff`（1755）、`removeChild`（1796）、`getTextForColumn`（2074付近）、[AttendanceModal.jsx](../../../src/components/AttendanceModal.jsx)。

### 記録・書類・一括入出力

- 支援結果・計画・支援項目・Forceシート・全体まとめは既存の保存／書出しデータとして維持する。新しいエディターが本文だけを更新した時に、残りの項目を空で上書きしない。
- 通信は日次の `reports` と児童別 `tree_communications` へ書くコードがある。新UIで片方だけを正本と決めつけず、連携時に更新結果・差分を扱う。
- CSV取込では対象事業所・日付・新規／既存・更新差分・定員超過を確認できること。未選択行やCSVにない児童を一括削除しない。
- バックアップ復元では日付・行の選択、未登録児童の登録確認、復元用データ列の有無を保持する。対象事業所を画面上で確認可能にする。
- 書出しの範囲（日・週・月・年・全期間）、全データCSV、書類CSV／Excel、既存日誌Excelへの反映、月間PDF印刷を残す。Excelの対象シートが見つからない際の確認も必要。
- 変更履歴は児童・日時・担当・対象項目・変更前後を残し、旧値をコピーできる。`onRestore` はAppから渡るが、現在の `LogModal` は受け取っておらず自動復元ボタンはない。
