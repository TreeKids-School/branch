## 1. 実装の範囲と現在の接続先

予約V2のスタッフ画面から起動する通信システムとして、`CommunicationApp.jsx` を接続の中心、`CommunicationWorkspace.jsx` を一覧・日報・業務操作の画面として再構成した。PCは一覧と比較を広く表示し、スマホは児童・日付・事業所を残し、一件ずつの入力と下部の保存操作を使う。設定・入出力もモバイル幅に対応した。予約V2側ではスタッフの表示名を起動情報へ渡し、スマホの初期表示を集中表示とした。iframeには印刷用ポップアップを許可する設定を追加した。画像の固定的な件数や例文をアプリへ埋め込んだものではない。

**予約V2内で動作する版は、現在もスタッフUID別のブラウザー内仮保存版である。** 次の作業は実施していない。

- V1の既存データを移行・変更・削除すること。
- 新しい共有サーバーへ接続すること、他のスタッフ・別端末へ記録を共有すること。
- V1のアクセス権を開発者だけへ変更すること。
- 予約側の児童・事業所・選択日を通信側へ自動で対応付けること。
- 通信を予約V2の保護者公開データへ反映すること。
- LINEへの自動送信、送信結果の取得、Instagram連携、写真取込み、AIバディの文章生成。

入力完了・コピー成功・手動送信確認は、それぞれ別の状態として保持する。どれも保護者公開の許可や実際のLINE送信結果とは扱わない。公開環境の既存データを使うテストも実施していない。

## 2. 保存先と反映の原則

以下のパスはアプリ内の論理保存先。ポータルビルドではFirebase互換APIをUID別IndexedDBへ差し替える。クラウドへの保存完了を意味しない。

| データ | 論理保存先・キー | 主な読取先 |
| --- | --- | --- |
| 当日児童・メモ・本文・予定・送迎・日報 | `reports/{officeId}_{YYYY-MM-DD}` の `children` / `messages` / `results` / `dailyTable` / `globalLog` | 業務表、通信一覧、メモ編集、日報、CSV、Excel、印刷 |
| 児童の個別通信写し | `children/{childId}/app_categories/書類管理/tree_communications/{officeId}_{YYYY-MM-DD}` | 通信側の個別記録。旧来の「日付だけ」の文書へ逆書込みしない |
| 記録のある日付 | `meta/reports_index_{officeId}.dates` | カレンダー、全期間・月間の書出し |
| 変更履歴 | `changeLogs/{officeId}_{YYYY-MM-DD}.logs` | 日付・事業所の履歴、児童絞込み、変更前のコピー |
| 職員勤務 | `attendance/{officeId}_{YYYY-MM-DD}` | 勤務画面、日誌Excel、当日・月間印刷 |
| タグ・挿入文・表示列 | `meta/tag_settings` | メモのタグ選択、定型文、業務表、CSV・Excel・印刷の分類 |
| スタッフ別挨拶 | `meta/greeting_templates` のスタッフ名キー | 担当変更時の挨拶挿入、通信エディターの挨拶挿入 |
| 名前チェックの除外語 | `meta/ok_words.words` | 通信本文の名前警告 |
| 編集途中の下書き | `localStorage` の `tree_tsushin_v2_editor_v2:{UID}:{officeId}:{date}:{childId}` | 本文・予定・未投稿メモの再開。保存済み記録とは別 |
| ポータルの実体 | IndexedDB `tree-tsushin-v2-browser-v1:{UID}` の `documents` ストア | 同じUID・同じブラウザーの記録。別UIDとは分離 |

`utils/commitDailyMutation.js` は最新の日報を読んで差分を適用し、日報・対象児童の個別写し・日付索引・今回の変更履歴を同じトランザクションで保存する。対象児童以外の記録や、今回扱わない旧データ項目は残す。本文だけの保存で、別欄の今後の予定を書き戻して消すことがないよう、変更した欄と編集開始時の値を渡す。

本文の競合は、編集中の値・編集開始時の値・保存済みの値を比較する。競合中は自動保存・コピー・入力完了を止め、残す内容を選んでもらう。通常の保存失敗は成功表示にせず、入力を残して再試行できるようにする。端末内下書きの保存に失敗した場合も警告を出す。

複数日CSV取込みは**日付・事業所ごとの保存**であり、ファイル全体の一括ロールバックではない。途中で失敗した場合は保存済み範囲を示す。バックアップ復元では保存済み行の選択を外し、再試行で未登録児童を重複作成しないよう、登録済みの対応を画面に残す。

### コピー・差込み・派生表示の違い

- メモのタグ分類は、保存されたメモと現在のタグ設定から表示時に計算する。タグの表示先変更は、業務表・書出しへ反映する。
- メモやプログラムを通信本文へ差し込む操作は、その時点の文章のコピー。元のメモやプログラムを後から変えても、編集済み本文へ自動反映しない。
- 【共有】新規メモから日報への転記も、作成時の追記。変更・削除の逆同期は行わない。
- 個別通信の写しは対象児童を保存する際に再生成する。タグ設定を変更した場合は、選択中の事業所・日付の個別写し備考も設定と同じトランザクションで再計算する。過去全日の個別写しを一括再生成する処理は追加していない。過去日の写しは次の児童保存時に更新される。過去日を含む業務表・CSV・印刷は正本と現在の設定から計算するため、設定変更を反映する。保護者公開への接続前に、正本から再計算するか、過去の更新対象を決める必要がある。
- `futurePlan` は見通しの文章であり、予約の日程データではない。
